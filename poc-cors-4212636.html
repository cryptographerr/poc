This page's origin

Two preconditions, or this page proves nothing.
  1. Open it over http(s), not file://. A file page has the opaque origin null, which is not equivalent to a real attacker origin and is rejected by at least one endpoint here. Serve the file from any origin you control.
  2. Sign in to the Merchant Portal in this same browser first. Without a session cookie for the API host, every call is an unauthenticated 401 and there is no data to steal.
Why this page does not print Access-Control-Allow-Origin. Browsers only expose CORS-safelisted response headers to JavaScript; the Access-Control-* headers are not on that list, so response.headers.get('access-control-allow-origin') is always null here even when the header is present. The proof is therefore behavioral: if the browser hands the body to this page, the origin was reflected and credentials were allowed — otherwise the fetch would have thrown. Read the echoed headers in DevTools → Network → Response Headers.
